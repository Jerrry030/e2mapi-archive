# E2M 事实基线补充（2026-07-20）

本文补充并修正 `fact-baseline-2026-07-19.md` 中与普通托管用户、自动接入和路由偏好有关的事实。发生冲突时，本补充优先；资金域和其他未变事项仍沿用 2026-07-19 基线。

## 角色与前端视角

- 截图中的“初始管理员 / 管理员”不是普通托管用户“小王”的视角。
- bootstrap 管理员不能与 `client` 业务角色组合，也不能仅靠右上角切换成“小王”。验收普通用户流程应创建并登录一个启用的 `client` 账号。
- `client` 可见的主菜单包括：实例管理、连接器、凭证管理、我的 API Key、账号健康、告警通知、待办审批、审计日志和账单与费用。
- 运维中心、上游编排、Key 交付配置、用户与权限等页面仍是管理员页面。

## Connector 就绪后的真实主路径

Connector 达到以下状态后，普通用户无需再点击“发布”“分配 Key”或“创建上游账号”：

- Connector 为 `online`，最近一分钟内有心跳；
- 网关已配置且测试结果为 `ok`，网关类型与实例一致；
- Binding 加密公钥有效；
- Connector 声明账号读取、Binding 安装/证明、调度屏障、账号创建/更新等必要能力。

自动 onboarding 默认启用，启动时立即扫描，之后默认每 15 秒扫描一次。它会为每个启用的 `client` 实例和每个 active 共享上游池执行：

```text
检查 Connector 和网关
→ 创建或复用 RoutePlan
→ 按不同来源分配独占 Key
→ 加密安装本地 Binding 并验证证明
→ 发布网关账号
→ 验证 PublishedBinding、远端账号和当前 Key 回执
→ 标记 active，并按分钟复核
```

管理员必须预先准备 active Pool、active Channel、稳定的来源标识、平台托管渠道的交付 Key、可用 Vault，以及足够的未分配库存。当前规则是所有 active Pool 自动覆盖所有符合条件的实例，不是由普通用户在前端选择 Pool。

普通用户成功后的推荐验收路径：

1. `接入与资源 → 连接器`：确认“在线”“网关测试通过”，无需操作发布按钮。
2. `接入与资源 → 我的 API Key`：确认已有分配记录，且本地 Binding 状态为已匹配/已验证。限时查看明文是可选动作，不是发布前提。
3. `监控与处置 → 账号健康`：选择路由偏好，并确认“已发布 > 0”“可调度 > 0”，查看 5 分钟 SLA、故障、恢复和最近切换结果。
4. `监控与处置 → 告警通知`：按需配置飞书、QQ 或 Webhook；这是建议项，不阻塞自动接入。

`实例管理 → 上游账号` 可用于核对远端账号已经存在且参与调度，但托管账号的正常调度归自动发布/自动切换流程所有，不应把手动启停或一键切换作为日常接入步骤。

## 失败可见性与当前 UX 缺口

- 普通用户没有完整的 onboarding 工作流进度页，也没有“立即重试”按钮。
- “我的 API Key”的空状态只显示尚未分配，不能解释是池、渠道、库存、交付 Key、Connector 能力还是发布步骤阻塞。
- 完整阶段、错误码、尝试次数和下次重试时间只在管理员的 `运维中心` 展示。
- 旧 `/onboarding` 接入向导仍把任意凭证和 RoutePlan 当作完成条件，与当前平台 Key 自动交付主路径不一致，不能作为权威进度页，也不应引导小王为了推进自动发布而随意创建凭证。
- Connector 未就绪时工作流默认约每 30 秒重试；其他可重试失败按 15 秒到 5 分钟指数退避；Pool 停用后工作流转 dormant。

## 下游用户路由偏好修正

2026-07-19 基线中“普通用户入口未实现、未接入生产替代排序”的表述已经过时。

- 普通 `client` 现在可在 `监控与处置 → 账号健康` 的“路由偏好”卡片选择：智能自动、价格优先、速度优先、成功率优先。
- `GET/PUT /api/v1/owner/routing-preference` 只允许当前 owner 读写自己的四档预设，不开放内部阈值、审批、冷却和防抖字段。
- 自动切换先用统一质量扣分执行平台安全筛选，再只在新鲜、样本充分且明确健康的备用来源中按用户偏好排序。
- 四种预设已经能在故障发生时选出不同的健康备用来源；它们不会仅因某个健康渠道更便宜或更快，就主动搬迁当前健康流量。
- “价格优先”当前按管理员维护的正数 `UpstreamChannel.CostHint` 排序，未知价格排后。这不是用户实际结算价，也不能作为钱包扣款或对账依据。
- 生效优先级仍为 `plan > pool > user > built-in default`，所以管理员设置的计划级或池级策略可覆盖用户级预设。

## 仍然有效的商业边界

- 平台钱包、可信用量金额、价格版本、充值入账、冻结/扣款/退款和余额权益门禁仍未形成闭环。
- 不能承诺按 token 实时准确扣款或绝不透支。
- 可以准确表述为：普通托管用户已可选择四档安全路由偏好，偏好已参与健康备用来源的故障切换排序；其中价格优先目前基于管理员成本提示，而非用户实际结算价。
